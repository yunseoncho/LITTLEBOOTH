# ADR-0004 iOS 앱 기술 스택: Expo(React Native, TypeScript) + 로컬 우선, 서버 없음(v1)

- 상태: 제안 (2026-11-11). `app/README.md`의 기존 계획(Flutter + Firebase)을 대체한다.
- 결정: **Expo SDK 58 + TypeScript**, 데이터는 **기기 안 SQLite**, v1은 **백엔드 없음**.

## 왜 바꾸는가 (기존 계획: Flutter + Firebase)
요구가 바뀌었다. 과금 요소를 모두 뺐고(ADR-0005), 비용이 들면 안 되며, 보안을 최우선으로 한다.

| 기준 | Flutter + Firebase | Expo + 로컬 SQLite (채택) |
|---|---|---|
| 서버 비용 | Cloud Functions는 유료(Blaze) 요금제가 필요. AI 프록시가 빠지면 Functions 이유도 사라짐 | 서버가 없어 0원 |
| 보안 면적 | 서버·규칙·키·App Check까지 관리 | 판매 데이터가 기기 밖으로 나가지 않음. 공격 면이 가장 작다 |
| 오프라인(행사장 전파 불량) | 동기화 큐를 직접 구현 | 처음부터 오프라인이 기본 |
| 개발 환경 | 이 클라우드 환경에 Flutter/Dart 없음 | 여기서 타입체크·테스트·번들까지 검증 가능 |
| 코드 재사용 | 프로토타입(JS) 로직을 Dart로 다시 옮겨야 함 | 프로토타입 계산 로직(정산·할인·재고)을 TS로 거의 그대로 이식 |
| 맥 없이 제출 | 어려움(맥 또는 유료 CI) | EAS Build/Submit으로 클라우드 빌드·제출 가능 |

## 비용·한도 (2026-11 조사, 출시 전 재확인)
- Apple Developer Program: 연 99달러 (피할 수 없는 유일한 고정비)
- EAS 무료 요금제: iOS 월 15회 빌드(저우선 대기열, 빌드당 45분 제한)로 안내하는 자료가 많으나 출처가 갈린다 → expo.dev/pricing에서 확인
- EAS Submit은 요금제와 무관하게 포함

## 대안과 보류 사유
- **SwiftUI(순수 네이티브)**: iOS 완성도와 무료 Apple 프레임워크(CloudKit·Vision·Translation) 활용은 가장 좋다. 다만 맥과 Xcode가 필요하고 이 환경에서는 컴파일 검증이 불가능하다. 안드로이드(M4)도 따로 만들어야 한다. 앱이 커져서 Expo의 한계에 부딪히면 이 경로로 이전한다. 이전 시 `app/src/domain`의 순수 함수와 테스트 벡터가 명세 역할을 한다.
- **Flutter**: 기존 계획. 위 표의 사유로 v1에서는 보류.
- **Capacitor(웹 래핑)**: 프로토타입을 그대로 감쌀 수 있어 가장 빠르지만, 앱스토어 심사 4.2(최소 기능, 웹 사이트를 앱으로 감싼 경우)에서 반려될 위험이 크다. 채택하지 않는다.

## 영향
- `backend/`(Firebase) 계획은 v1에서 사용하지 않는다. 동기화·백업이 필요해지면 CloudKit(사용자 iCloud 용량으로 저장돼 개발자 비용 0)을 먼저 검토한다.
- 계정·로그인이 없어서 "Apple로 로그인 필수" 심사 규정(4.8)도 해당되지 않는다.
- 되돌리기 쉽다: 도메인 로직은 프레임워크와 무관한 순수 TS로 둔다.
